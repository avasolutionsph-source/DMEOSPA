API Overview

Base URLs

  • Marketing API: https://ava-marketing-api.onrender.com
  • PWA Backend: https://ava-pwa-backend.onrender.com (if deployed)
  • Local Development: http://localhost:3000

Architecture Overview

The Ava Solutions system consists of multiple API layers:

  • Marketing Website API - User management, subscriptions, sync
  • PWA Backend API - Business data, transactions, employee management
  • Internal APIs - Health checks, monitoring, feature flags

Data Flow

The system follows this data flow pattern:

  1. User authentication via Marketing API
  2. Business data stored locally in IndexedDB
  3. Optional sync with PWA Backend for cloud storage
  4. Real-time updates and monitoring via internal APIs

Authentication

Authentication Methods

  • JWT Tokens: Primary authentication method
  • OAuth 2.0: Google and Facebook login
  • Session-based: For admin panel access

Token Format

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Token Payload Structure

{ "userId": "user_id_here", "email": "user@example.com", "role": "customer|admin|superAdmin", "subscriptionPlan": "unpaid|pro", "businessName": "Business Name", "iat": 1634567890, "exp": 1634654290 }

Authentication Endpoints

POST /api/auth/register Register new user account

Request Body

Parameter Type Required Description
email string Yes User email address
password string Yes Password (min 6 characters)
firstName string Yes User first name
lastName string Yes User last name
businessName string Yes Business/spa name
phone string No Phone number
plan string No Subscription plan (unpaid|pro)

Example Request

POST /api/auth/register Content-Type: application/json { "email": "owner@myspa.com", "password": "securepass123", "firstName": "Jane", "lastName": "Smith", "businessName": "Relaxation Spa", "phone": "+63 912 345 6789", "plan": "pro" }

Webhooks

Currently, the system does not implement webhooks, but they could be added for:

  • Payment notifications - For subscription management
  • Sync events - When data is synchronized between systems
  • User events - Registration, login, subscription changes
  • Error alerts - Critical system errors and downtime

Future Implementation

Webhooks could be implemented to notify external systems of important events. The structure would follow industry standards with JSON payloads and signature verification.

Error Codes & Handling

Standard HTTP Status Codes

  • 200 - Success
  • 201 - Created (successful registration/creation)
  • 400 - Bad Request (validation errors)
  • 401 - Unauthorized (invalid credentials/token)
  • 403 - Forbidden (insufficient permissions)
  • 404 - Not Found (resource doesn't exist)
  • 429 - Too Many Requests (rate limited)
  • 500 - Internal Server Error

Error Response Format

{ "error": "Error message", "details": "Additional details (optional)", "code": "ERROR_CODE (optional)", "timestamp": "2024-01-20T10:30:00Z" }

Common Error Messages

Error Status Description
User already exists with this email 400 Registration with existing email
Invalid credentials 401 Wrong email/password combination
No token provided 401 Missing Authorization header
Admin access denied 401 Non-admin user accessing admin endpoint
Validation failed 400 Request body validation errors
Too many requests 429 Rate limit exceeded

Rate Limiting

The API implements rate limiting to prevent abuse:

  • Limit: 1000 requests per 15 minutes per IP
  • Headers: Rate limit info returned in response headers
  • Scope: Applied to all /api/* endpoints
